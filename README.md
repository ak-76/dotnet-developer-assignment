## The Assignment

We need a small backend service for managing vehicle service cases.

A service case represents an issue reported for a vehicle.

Each case should contain the following fields:

| Field | Description |
|---|---|
| `Id` | Unique identifier generated by the application |
| `Vin` | Required, 17 character Vehicle Identification Number (VIN) |
| `CreatedAt` | Creation timestamp generated by the application in UTC |
| `Status` | Current status of the case, initially `New` |
| `Description` | Required, non empty description of the reported issue |

A case can have one of the following statuses:

- `New`
- `InProgress`
- `Completed`
- `Cancelled`

### Business rules

Every new service case must start with the status `New`.

The following status transitions are allowed:

| Current status | Allowed next status |
|---|---|
| `New` | `InProgress`, `Cancelled` |
| `InProgress` | `Completed`, `Cancelled` |
| `Completed` | None |
| `Cancelled` | None |

- Return an appropriate HTTP error if the status is invalid or the transition is not allowed. Do not change the existing case.
- `Completed` and `Cancelled` are final statuses and cannot transition to another status.
- Requesting the current status again should succeed without changing the case.

## Functional requirements

The operations below are listed in the recommended order of implementation. Focus on the higher-priority operations first. If time is limited, it is fine to leave lower-priority operations unfinished.

The application should contain some initial sample service cases with different statuses so that the operations can be tested without having to create new cases first.

### 1. Get service cases

Return the available service cases. Support optional filtering by VIN and status. Both filters should work together.

Return all cases if neither filter is provided, and an empty collection if there are no matches. Return a client error for an invalid status filter.

### 2. Get a service case

The API should return the requested case by its ID or an appropriate response if the case does not exist.

### 3. Update the status of a case

Allow the caller to update the status of an existing service case.

Example request body:

```json
{
  "status": "InProgress"
}
```

Apply the status transition rules described above. Return an appropriate response if the case does not exist or the requested status change is not allowed. The case ID, VIN, description and creation timestamp must remain unchanged.

### 4. Create a service case

The caller provides the VIN and description. Both fields are required and must not be empty or contain only whitespace. The VIN must be exactly 17 characters long. No further VIN validation is required.

The application generates the case ID and UTC creation timestamp and sets the initial status to `New`.

Example request body:

```json
{
  "vin": "YV1ABC12345678901",
  "description": "Vehicle reports a charging problem"
}
```

Example response body:

```json
{
  "id": 123,
  "vin": "YV1ABC12345678901",
  "status": "New",
  "description": "Vehicle reports a charging problem",
  "createdAt": "2026-11-24T09:30:00Z"
}
```

## Technical requirements

Please use:

- **C#**
- **.NET 10 or later**
- **ASP.NET Core Minimal APIs**

For data storage, use either:

- In-memory storage / collection
- simple db (e.g. SQLite)

Your solution should preferably also include:

- request validation
- Appropriate HTTP status codes
- Basic error handling
- At least a couple of automated tests covering functionality you consider important
- A project structure suitable for the application

You can use unit tests, integration tests or both.

The application should run locally. Authentication, cloud services and Kubernetes support are not required.

### Bonus - not required

If you have time, you can also try either or both:

- Containerize the application and include instructions for building and running it.
- Add a simple Blazor UI for viewing service cases, creating new cases and updating their status.

Focus on the backend requirements first. The bonus tasks are optional.
